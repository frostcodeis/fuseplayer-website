Privacy Policy.

Fuse Player · Last updated: 28 October 2026

Your media can generate online requests. Fuse Player automatically looks up library titles through TMDB, including titles derived from local files and folders. Opening subtitle search contacts external providers. Playback diagnostics may also be processed by Android and, depending on device settings, Google or the device manufacturer. The sections below explain these activities and your available controls.

1. Who we are and what this policy covers

FrostCode develops Fuse Player (also referred to as FusePlayer), a media player for Android TV, Google TV, Android phones and tablets. Contact us about privacy or your data at frostcodeis@gmail.com. This policy describes the app implementation reviewed on 28 October 2026 and this product website. It also distinguishes processing by the app from processing by external providers.

2. Data on your device

The app accesses media files and folders you select, stores library and connection settings, and keeps playback history and progress locally. It can store network credentials, subtitle-service account details, user-provided API keys, Trakt tokens, cached metadata and images, and downloaded subtitle files. Local playback does not upload the video file to TMDB or subtitle-search APIs, but titles derived from that library can be sent for metadata and subtitle searches.

The audited release does not use a FrostCode-operated application backend. Local history is not synchronized to Trakt in this implementation. Titles shown in Continue watching can nevertheless cause TMDB lookups; local history storage does not mean there are no requests concerning those titles.

3. Automatic metadata and artwork: TMDB

Fuse Player automatically contacts api.themoviedb.org to find titles, descriptions, ratings, artwork and episode information. Requests can include a cleaned title derived from a file or folder name, the year when available, the interface or system language, and a series identifier and season number. The app also sends its API key and client identification. Artwork requests to image.tmdb.org identify the requested image and size.

These requests can occur for the home library, folders, detail screens and Continue watching, including media on USB or local storage. The current app has no separate metadata opt-out; turning off automatic scanning does not disable all metadata lookups. Cleaning a filename removes some technical markers; it does not anonymize it or reliably identify private videos. Avoid adding files or folders with names you do not want disclosed through these lookups. Network recipients can see the public IP address from which a request arrives.

4. Subtitle searches, accounts and downloads

Subtitle features are optional, but opening the subtitle panel starts a search automatically, before you enter a new query or press a search button. Changing the language or provider can start another request. Requests can include the media title or text you enter, subtitle language, and season and episode numbers.

  • OpenSubtitles: the initial OpenSubtitles search uses both rest.opensubtitles.org and api.opensubtitles.com. The .org search receives the query and language or episode details without the saved .com account credentials. The .com API also receives an API key; when saved account details are used, your username and password are sent for authentication, followed by use of an access token. Download requests identify the subtitle file.
  • Napisy24 (napisy24.pl): selecting this provider sends the search query and the account username and password used for that service.
  • SubDL (api.subdl.com): requests send the title, language, relevant episode information and your API key. The key is included in the request URL. Without a user key this API is not called, but the OpenSubtitles.org fallback can still run.

Empty results from Napisy24 or SubDL can automatically trigger a search on OpenSubtitles.org. Failure to obtain an OpenSubtitles.com download link can also cause an additional .org search. A query is therefore not necessarily sent only to the last selected provider.

Selecting a result downloads a subtitle from the URL returned by the provider. This may use dl.subdl.com or another host or content-delivery service. The download recipient receives the requested path, any parameters in the supplied link, client headers and your connection IP address. Downloaded subtitles can be stored locally and reused. API authentication and subtitle search do not give FrostCode control over a provider's accounts or server logs.

5. Connecting a Trakt account

Trakt connection is initiated when you choose to connect your account and approve the device code through Trakt. Fuse Player contacts api.trakt.tv to obtain the pairing code and poll for authentication tokens. Requests include the application client identifier and device code. The app does not ask you to enter your Trakt password in its own form.

In the audited implementation, Trakt is used for account connection and token storage. Fuse Player does not send viewing history, playback progress, ratings or watch timestamps to Trakt. Token refresh code exists but is not actively called. Removing tokens in the app removes the local copy; it does not revoke authorization at Trakt or delete your Trakt account. Manage authorization and account deletion directly with Trakt.

6. Your servers, streams and document providers

When you add a network source, test it, scan it or play media, the selected server receives authentication information where required and requests for directory listings, file paths and media byte ranges. Later automatic scans can use saved credentials without asking again. The app supports FTP, SMB, SFTP and user-supplied HTTP/HTTPS URLs; any tokens you include in a URL are part of the request.

FTP sends credentials and traffic without TLS. SMB uses its authentication protocol, but the app does not enable or guarantee SMB session encryption. SFTP uses encrypted SSH and checks the server key against the accepted pin. HTTPS protects traffic using TLS; HTTP does not. Whether a cleartext HTTP URL is allowed also depends on Android's network policy. Dynamic subtitle links are not restricted by app code to a fixed list of hosts or to HTTPS. Not all app traffic is encrypted.

The Android file picker may expose local, USB or cloud-backed document providers. A cloud provider you choose can process listing and read requests under its own policies. User-configured servers and providers have their own logging and retention practices.

7. Playback diagnostics and other system mechanisms

The audited release contains no Firebase Analytics, Crashlytics, Sentry or advertising SDKs and no separate commercial analytics collector configured by FrostCode. This is not a statement that there is no telemetry.

On Android 12 and later, Media3 has platform playback diagnostics enabled when the system service is available. It reports to Android MediaMetrics information such as playback events and timings, errors, network type, codecs and formats, resolution, frame rate, media language and duration, frame and byte counters, player version and a system diagnostic session identifier. Android may further collect or transmit diagnostics through Google or the device manufacturer depending on system settings. There is no separate Fuse Player switch for this reporting. Review your device's usage and diagnostics settings; availability and behavior vary by device. FrostCode does not determine the system's later upload endpoint or retention period.

Emoji2 can automatically request an emoji font from a system font provider after app startup. Any download by that provider follows its implementation. This font request does not include film titles or account passwords from the app.

The audit found no app code reading advertising ID, IMEI, GPS location, contacts or microphone recordings for transmission. External network recipients still see the connection IP address, and platform diagnostics use a system session identifier.

8. Saved credentials and security

Saved network passwords, subtitle credentials, user API keys and Trakt tokens are protected with AES-256-GCM using a device-generated key managed by Android Keystore in the reviewed implementation, after the required migration of older stored credentials. This protection applies to saved credentials, not every item of app data or every network connection. Hardware-backed protection and StrongBox are not guaranteed on every device.

Production logging includes redaction of sensitive URL and authentication fields. The audit found no intentional logging of passwords or tokens. These safeguards do not determine what external services log. No security mechanism guarantees protection in all circumstances.

9. Backups, device transfer and background activity

Android backup remains enabled. Backup rules exclude the DataStore containing account, connection and history data, and exclude saved SFTP server-key pins. A reported backup-and-restore test confirmed that saved credentials and tokens were not restored. Android 12+ device-to-device transfer testing was not yet confirmed when this policy was updated; we do not claim a tested guarantee for every device transfer.

Downloaded subtitle files and their filenames are not excluded from Android backup. Eligible files may be processed by your device's backup transport, including a cloud or manufacturer service, according to system settings and that service's policies. Removing local data does not necessarily remove historical backups.

Hiding the app does not guarantee an immediate end to network traffic. Started metadata queries, image and subtitle downloads, Trakt pairing requests, scans or buffering can continue while an activity remains alive. System diagnostics and backups run under system control. The audited app has no dedicated scheduled synchronization service; that does not mean there is no background processing.

10. Retention, deletion and your choices

Use Settings → Accounts and connections to remove the selected account and connection data offered by the app. Removing local credentials does not erase a provider's server logs, delete an external account, revoke a Trakt authorization or remove existing system backups. Android's app-storage controls can clear app-managed local data; this does not delete source videos stored elsewhere or data retained by an external provider. Previously granted access and external accounts should also be managed through Android and the relevant provider.

Local library, history and saved settings support ongoing use and remain subject to the app's available deletion and Android storage controls. Downloaded subtitles and caches are separate from saved credentials; removing an account should not be treated as removal of every local file.

External providers may retain requests, account records, API usage and server logs. We cannot verify a single retention period for all API and system processing, and do not promise that requests are processed only ephemerally. The SubDL policy expressly covers API requests and describes logging and API quota accounting. Other published policies may focus on their websites rather than specify retention for every API operation. Their own current policies and responses govern their practices; FrostCode cannot delete those records on your behalf.

You can avoid subtitle queries by not opening subtitle search, refrain from connecting optional accounts, remove saved connections, and review system diagnostics and backup settings. There is currently no independent app control to stop every automatic TMDB lookup while continuing to use the library.

11. Provider information

For providers' information and privacy contacts, consult TMDB, OpenSubtitles.com, OpenSubtitles.org, Napisy24, SubDL, Trakt and your device manufacturer's documentation. The OpenSubtitles.com policy should not be assumed to settle every .org API practice. Providers may process information in countries different from yours; we do not promise that all processing stays within your country or the EEA.

12. Support, website and privacy requests

If you email FrostCode, we receive your email address, message and any attachments through email providers. We use what you provide to answer and investigate your request. Do not send passwords, tokens or unnecessary personal information. You can request access, correction or deletion of information you have sent to us at frostcodeis@gmail.com. We assess requests under applicable law; information may need to be retained for unresolved support or legal obligations. No fixed deletion period for support correspondence is promised here.

Depending on applicable law, you may also have rights to restriction, objection, portability and to complain to a data-protection authority. Requests concerning external accounts or provider logs should be directed to that provider. Local data that is not held by FrostCode can be managed on your device.

This website is hosted by GitHub Pages. Its host processes site requests under the GitHub Privacy Statement. This site's current pages do not embed analytics or advertising scripts; hosting and email processing are separate from app processing.
