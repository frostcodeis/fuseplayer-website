Privacy information.

FusePlayer · Prepared 27 October 2026

Policy draft — release verification pending.
This page records the available implementation review and its limitations. It is not a final privacy policy for the released app. Telemetry, diagnostics and other data flows still require verification against the Android release before final disclosures can be published.

Developer and contact

FusePlayer is developed by FrostCode for Android TV, Google TV, Android phones and tablets. For privacy questions, contact frostcodeis@gmail.com.

Local media and network sources

FusePlayer plays user-provided local videos and media from configured FTP servers and SMB shares. Connecting to a server involves communication with that server. Access credentials are used when the server requires authentication. The completed policy must confirm the precise media metadata, settings, playback records and other data retained by the release.

Saved credentials: implementation review

The implementation review supplied during development reports AES-GCM encryption for newly saved network passwords, subtitle-service credentials, user-provided API keys and Trakt authentication tokens. It reports that encryption keys are generated on the device and managed through Android Keystore.

This describes encryption of saved credentials, not all app data or network traffic. Hardware-backed protection and StrongBox are not guaranteed on every device.

Older installations: the review identified an asynchronous migration of previously stored credentials. If migration fails, older values may remain unencrypted. Verification of the migration fixes is still pending, so this page does not claim that every existing credential is encrypted.

Backups

The supplied review reports Android backup rules excluding the DataStore directory from system backup, including cloud backup and device transfer rules for newer Android versions. These are configuration findings; a complete backup-and-restore test has not yet been confirmed. They do not cover historical backups or manual copies made with root access.

Subtitle services and Trakt

FusePlayer includes integrations with external subtitle services and Trakt. Using a connected integration can send authentication information and requests to the relevant service. Subtitle credentials are sent to the subtitle provider during authentication; Trakt authentication uses tokens.

The final policy must identify the providers in the release and verify the exact information sent for subtitle requests and Trakt functions, including whether media identifiers, file hashes, viewing activity or account information are transmitted. We are not presenting those unverified fields as confirmed behavior.

External services have their own privacy terms. Review the terms for the service you connect. Disconnecting an integration and revoking access at the provider may be separate actions; release-specific removal instructions are still to be verified.

Network security

Ordinary FTP is supported and does not encrypt traffic. Saved-password encryption does not make an FTP connection encrypted. Protection of other connections depends on the protocol, server and implementation. We do not claim that all transmissions are encrypted or that data never leaves your device.

Telemetry and diagnostics: pending verification

The release audit must still establish whether analytics, crash reporting, advertising SDKs, diagnostic logs or other telemetry are present; what data they process; where that data is sent; and how long it is kept. No “no tracking”, “no collection” or “no sharing” declaration is made while these checks are incomplete.

Support messages and this website

If you email support, the message includes your email address, the information you provide and any attachments. Email providers process those messages. Please avoid sending passwords, tokens or unnecessary personal information.

This website is hosted on GitHub Pages. The hosting provider may process request information under the GitHub Privacy Statement. This page should not be read as a claim that visiting the website involves no data processing.

Before the policy is finalized

The release review must confirm all data categories, purposes, recipients, retention periods, deletion and revocation controls, applicable privacy rights, and any relevant age or regional requirements. These findings must also be checked against the Google Play Data safety disclosures.

The final policy will be published here after those checks. Until then, this draft should not be submitted as the app’s completed privacy policy in Google Play Console.
